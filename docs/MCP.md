# Turnmark MCP

Local stdio and a Cloudflare Worker adapter use the same tool server. The
remote URL is `https://mcp.turnmark.app/mcp`; protected main CI owns deployment
to the dedicated Worker and Custom Domain. The local server is published as
[@turnmark/mcp@0.2.0](https://www.npmjs.com/package/@turnmark/mcp); it includes
the SDK dependency and requires no Rust toolchain to install.

The current source prepares `0.3.0` with SDK `0.2.0`: an optional Colorado
Timing method, collapsed method setting, source discovery and additive offsets,
plus the shared vector glyphs and wordmark. NCAA remains the default. The npm
release remains `0.2.0`; publish SDK `0.2.0` before MCP `0.3.0`. Publication is
separate from protected main CI updates to the hosted Worker.

The public [MCP quick start](https://turnmark.app/mcp/) covers hosted connection
settings and links to the [Markdown reference](https://turnmark.app/mcp/index.md).
The website footer links to the setup guide; page metadata identifies
[llms.txt](https://turnmark.app/llms.txt) for agent discovery.
The build publishes the canonical package README as that Markdown reference;
update `packages/mcp/README.md` rather than maintaining a second copy. The
`llms.txt` index follows the [llms.txt proposal](https://llmstxt.org/); it documents
available integrations and does not implement WebMCP or expose personal data.

## One calculation engine

`packages/mcp` registers seven read-only tools in the current source adapter around `@turnmark/sdk`.
`packages/mcp-worker` supplies stateless Streamable HTTP using the same server
factory. Node loads the packaged Wasm bytes; Workers imports a bundled,
precompiled `WebAssembly.Module`. Each HTTP request gets a fresh protocol server;
only the immutable calculation engine is cached across requests. There is no
second numerical implementation or copied dataset.

Both adapters preserve the SDK's structured outcomes, provenance, source
editions, actual event distances, and published/derived kinds. Shape validation
belongs to the protocol adapter; time parsing, editions, age/event coverage,
ranges and calculations remain in Rust. Malformed arguments are protocol/tool
errors. Well-shaped requests can return `invalid` or `unavailable` as ordinary
calculation results. Qualifying targets are benchmarks, not entry eligibility.

The CLI uses the current official MCP SDK's stdio entry, with stdout reserved
for protocol traffic. The Worker uses Cloudflare's stateless handler, with
legacy compatibility for ordinary clients. There are no persistent sessions,
SSE subscription streams, task queues, OAuth accounts or personal-history access.
See [client setup and tool arguments](../packages/mcp/README.md).

## Local development and verification

```sh
npm ci
npm run test:mcp
npm run build --workspace @turnmark/mcp-worker
npm run dev --workspace @turnmark/mcp-worker
```

The package test packs and installs both SDK and MCP tarballs outside the
workspace with lifecycle scripts disabled. It runs actual client discovery and
all 50 non-parser portable cases through stdio and local workerd, in legacy and
2026-07-28 modes: 53 exact SDK-result comparisons and eight malformed argument
cases per transport/mode. The local server runs with fetch disabled. Checks also
cover source metadata, unknown tools, extra arguments, cancellation/recovery,
missing Wasm startup failure, route/method/Origin rejection, oversized bodies,
per-IP and aggregate rate limiting (including health probes), and clean teardown. Runtime/binding declarations are generated by
Wrangler and ignored; `npm run check --workspace @turnmark/mcp-worker` regenerates
them before type checking. No Cloudflare credentials are required.

The Worker limits POST bodies to 16 KiB before parsing, including the legacy
compatibility classifier. It accepts only `/mcp` POSTs and has explicit Host and
browser Origin allowlists; CORS is disabled. Non-browser clients without Origin
can connect. The root GET endpoint returns service/version information.
Cloudflare rate bindings allow 180 requests per IP per minute and 600 requests
per minute across all callers in a location. Both include health probes, run
before engine work and reply `429` with `Retry-After: 60`. Limits are approximate
and per-location, not precise global quotas. JSON content type is required.
The Brianna Stanback account was confirmed on Workers Free: no plan upgrade is
part of this rollout. Cloudflare enforces its free CPU allowance and shared
account request quota; exhausting that quota makes the remote service
unavailable instead of incurring paid overage. Local calculations remain
available. Keep Workers on Free unless the owner explicitly approves a change. There are no outbound fetches, arbitrary URL
inputs or storage bindings. Operational errors use fixed event names, without
logging calculation inputs. Cloudflare still processes remote requests; use
local stdio when inputs should remain on-device.

## Production boundary

The Worker is named `turnmark-mcp`, separate from `turnmark-web`. Its Custom
Domain owns `mcp.turnmark.app` DNS and TLS; do not add a conflicting manual CNAME
in the IaC repository. Website deployment credentials must not gain access to
this Worker, and account-wide/IaC tokens must not enter this public repository.

Before the first production deployment:

1. Create the dedicated Worker and Custom Domain in the Brianna Stanback
   Cloudflare account, with `workers.dev` and preview URLs disabled. The
   initial bootstrap must install the rate binding/configuration from
   `packages/mcp-worker/wrangler.jsonc`.
2. Create a short-lived Editor deployment token restricted to `turnmark-mcp`.
   Store it only as `TURNMARK_MCP_DEPLOY_TOKEN` in the GitHub
   `cloudflare-mcp-production` environment, restricted to `main`.
3. Review and merge this branch. The shared-engine workflow tests and bundles
   the Worker without credentials. After all selected engine checks pass, a
   new runner downloads that same-run artifact, installs only isolated pinned
   deployment tooling without lifecycle scripts, uploads a version without
   changing routes, and deploys exactly its returned version ID. PRs cannot
   enter this environment or access its secret.
4. Verify root health and real MCP discovery/calls against the live hostname.
   Keep rollout status accurate here and in the package README.

The account bootstrap and protected secret are configured. The deployment
token expires January 16, 2027; rotate it before expiration using the same
individual-Worker scope. Ordinary web-only edits skip MCP jobs;
SDK/core edits test their MCP consumer. There is no automatic npm publication
of `@turnmark/mcp`; it depends on a released SDK and separate package release
setup. WebMCP and publisher embeds have independent adapters and scopes.

Superseded PR checks may be canceled, but main-branch engine runs finish before
the next run can deploy. This prevents a web-only merge from canceling a pending
MCP release and then skipping its replacement. Live verification checks all seven
tools and the current versioned Apps resource; a healthy root alone does not
confirm that the intended update deployed.

The private IaC repository manages the zone's Free-plan edge rules: a
path-only `/mcp` limit of 30 requests per 10 seconds per IP/location, with a
10-second block, and hostname-specific route filtering. A disabled emergency
stop can block the MCP hostname without changing the website. Unsupported MCP
methods reach the Worker and return `405`; there are no interactive browser
challenges. Edge limits and the Worker's bindings reduce abuse but cannot
guarantee availability against distributed traffic or enforce a global daily
budget. Do not broaden the deployment token to manage these rules.

Sources: [official TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk),
[Cloudflare stateless MCP handler](https://developers.cloudflare.com/agents/model-context-protocol/apis/handler-api/),
[Workers Wasm](https://developers.cloudflare.com/workers/runtime-apis/webassembly/),
[rate limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

## Explicit benchmark previews

`assess_swim_benchmark` and `get_world_points` default to their original-swim
behavior. An optional `preview` object explicitly requests a destination course,
method and altitude policy before the lookup:

```json
{
  "swim": {
    "time": "58.32",
    "event": { "distance": 100, "stroke": "freestyle", "course": "SCY" }
  },
  "table": "women",
  "preview": { "to": "LCM", "method": "ncaa-2025-27" }
}
```

This is a `get_world_points` example; standards also need `system` and any
applicable `age`. Optional `preview.elevation` and `preview.altitudePolicy`
use the same contract as `convert_swim`. Conversion happens once through the
shared engine; lookups use its returned destination event and clock.
`assessmentContext` retains `basis: "converted-estimate"`, `originalSwim`,
`assessedSwim`, the complete conversion outcome/provenance and the requested
preview options. A failed conversion returns its invalid/unavailable outcome,
with `assessedSwim: null`; it never assesses the original silently.

Hosts must display preview points/thresholds as estimates, not actual
performances, personal bests or proof of qualification. No history is read or
changed. The widget and MCP Apps card remain conversion-only.

## MCP Apps conversion UI

The source adapter/server version is `0.3.0`, using SDK `0.2.0`.
The official Apps extension adds metadata/resource discovery to `convert_swim`;
the six original tool names and text/structured fallback remain. The source
adapter also adds `assess_swim_benchmark` for original-swim standards, including
Futures, Junior Nationals and NISCA; published npm 0.2.0 still has six tools. `convert_swim` accepts
the optional method; `get_sources` additionally lists conversion methods.
Registration is static: a fresh per-request stateless server cannot reliably
infer initialized UI capabilities during construction. Hosts choose whether to
render the resource. Both clients with and without Apps are tested in both
supported protocol modes.

The UI resource is self-contained HTML, generated before TypeScript compilation
from `packages/mcp/ui`, shared CSS tokens and `design/wave.svg`. No Wasm, numerical
tables, CDN, nested widget iframe or direct network calls are included. The
official `App` bridge sends explicit conversions to the host, which retains tool
approval and link permissions. CSP requests empty network/resource/frame domain
lists. The card stores no data beyond its own live instance; two cards are
isolated. A cancellation invalidates pending responses before they can replace
the committed result or conversation context.

`npm run test:mcp` builds/types the card, exercises fresh packed offline consumers
and workerd, then runs the official `AppBridge` in a strict opaque-origin sandbox
with real stdio and Workers HTTP tool calls. Install Chromium first. The isolated deployment still
uploads only the already-tested Worker artifact; the UI does not change token,
route, rate-limit, billing or credential boundaries. The HTML has a 750,000-byte
build budget (including the official bridge SDK); Worker size remains checked by
Wrangler. See [MCP Apps review](MCP_APPS_REVIEW.md) for measurements, screenshots,
remaining host acceptance and publication status.
